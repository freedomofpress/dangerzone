Changelog¶

All notable changes to this project will be documented in this file.

The format is based on Keep a Changelog since 0.4.1, and this project adheres to Semantic Versioning.

Unreleased¶

Changes¶

  • We no longer render the Github release notes from Markdown to HTML within the Dangerzone application. This unfortunately makes release notes less readable, but most importantly, it reduces our application's attack surface. (1542)

Added¶

  • Accept documents from stdin, and write safe PDFs to stdout, by passing - as the input filename and --output-filename - for the output, enabling standard Unix pipe workflows like cat file.pdf | dangerzone-cli - -o - > safe.pdf (#1522)

Fixed¶

  • Accept OCI image indexes as multi-arch container images, in addition to Docker manifest lists. BuildKit 0.31.0 and later pushes OCI image indexes by default, which made dangerzone-image prepare-archive fail with InvalidMutliArchImage against newly published images (#1534).
  • Respect's user choice to disable or skip update checks (#1517, #1543)
  • Alert users when a file can't be processed due to a permission error (#1513)
  • Build Qubes packages from tagged released of the https://github.com/freedomofpress/dangerzone-image repo (#1545)
  • Fix two small copy issues in the wording of the "download sandbox" dialog (#1578)

Platform changes¶

  • Add support for Fedora 45 (#1568)
  • Add support for Ubuntu 26.10 (Stonking Stingray) (#1569)

Development changes¶

  • The documentation is now published at https://docs.dangerzone.rocks (#903)
  • Add a security policy for our project (#1278)
  • Set the severity cutoff of our code scans from Critical to High, on a biweekly basis (#1438)

0.11.0¶

Changes¶

  • Linux packages dropped the container.tar file. It is expected to be downloaded at the first usage, and then kept up to date. If you prefer to use packages with the container.tar, use the dangerzone-full variant (#1069)
  • Breaking change (Linux CLI): with the slim dangerzone package, the CLI no longer auto-downloads the conversion sandbox. New installations must initialize the sandbox once with dangerzone-image upgrade (or run the GUI, which prompts for the download) before dangerzone-cli can convert documents. Users of the dangerzone-full package or who already have an image installed are unaffected.

Fixed¶

  • Remember user-selected output directory across sessions (#1123)
  • Fix default PDF reader selection on Linux (#814)
  • Update the theme correctly on dark/light mode changes (#1238)
  • Update Linux .desktop file with missing MIME types for HWP and ODF formats (#646)
  • Elide long filenames in the filename label to prevent UI elements from being pushed off-screen (#143)
  • Fix macOS app bundle build, which crashed at startup with module 'dangerzone' has no attribute 'main' after the CLI parsing refactor (#1470)

Added¶

  • Dangerzone is able to function without a bundled container.tar file (#1400)
  • Look for desktop entries in XDG_DATA_DIRS paths on Linux (#1413)
  • It is now possible to convert another set of documents after a first batch (#549), or add more documents to an ongoing conversion (#1464)
  • OCR tasks are now queued, resulting in up to x6 speedup (#1329)

Platform changes¶

  • Add support for Ubuntu 26.04 (Resolute Raccoon) (#1467)
  • Drop support for Ubuntu 25.04 as it has reached end of life (#1468)
  • Add a deprecation warning for Windows 10 (#1357)
  • Add support for Fedora 44 (#1462)
  • Drop support for Fedora 41 and Fedora 42 as they have reached end of life
  • Drop support for Debian bullseye (#1482)

Development changes¶

  • Run macOS Intel CI tests only on scheduled/manual runs to reduce PR CI time (#1338)
  • Pin Podman to v5.x.x, to support Windows 10 installations for one last release (#1357)
  • Move the conversion error definitions out of the now-removed conversion/ package and into dangerzone.conversion_errors, so the host code keeps a single source of truth for the error codes raised inside the sandbox.
  • Move the code for the container image into a separate freedomofpress/dangerzone-image repository. CI now consumes the published image via dangerzone-image prepare-archive instead of building it in-tree, and the resulting container.tar is cached against the registry digest.
  • Drop the format-specific conversion tests and their sample assets. The remaining tests cover the host-side isolation provider interface only; document-format coverage now lives alongside the container image in freedomofpress/dangerzone-image.
  • Narrow the isolation provider tests to the host/sandbox interface (max-pages and max-dimensions client enforcement, error propagation), using a single canonical sample PDF.
  • Run the GUI tests headless by default via QT_QPA_PLATFORM=offscreen and drop the xvfb/xvfb-run setup from CI. A new --onscreen pytest flag re-enables the on-screen mode for local debugging.
  • Run pytest with pytest-xdist and group container-backed and GUI tests into dedicated xdist_groups so each group runs on a single worker, avoiding contention over the container runtime and the offscreen Qt platform.
  • Pin XDG_DATA_DIRS in the GUI logic tests that walk it for .desktop files, so the tests don't pick up arbitrary entries from the developer's or CI runner's environment.
  • Bump vfkit to 0.6.3 (now signed upstream, switching to vfkit-unsigned with a relaxed >=0.6.1 pin) and cosign to 2.6.3 in mazette.lock, and regenerate poetry.lock with Poetry 2.3.
  • Update the build instructions for Qubes, in order to work with the new dangerzone-insecure-converter-qubes RPM package. (#1463)
  • Drop the cx_Freeze < 8.5.0 workaround now that the upstream MSI build bug has been fixed (#1443)
  • Extend dev_scripts/env.py to create end-user Dangerzone environments from our APT/YUM repos, with the --qa / --prod flags

0.10.0 - 2025-12-02¶

Added¶

  • Sign the sandbox/container images and automatically upgrade them to their latest version (#1006). Read more about this feature in our docs.
  • Make Dangerzone use an embedded version of Podman under the hood (#1145)
  • Bundle Podman images for Windows and macOS alongside our application (#1170)
  • Introduce a new CLI helper called dangerzone-machine to manage the Podman machine the Dangerzone uses under the hood (#1172)
  • Capture all the command outputs in the logs (#1236)
  • Make the podman pull command and registry lookups go through Tor on Tails (#1335)
  • Add a startup task that installs WSL (#1312)

Removed¶

  • Docker Desktop is no longer required to run Dangerzone. In fact, they are no longer compatible, due to some changes in the bundled container image. Instead, Podman Desktop is used under the hood (#118)

Fixed¶

  • Fix a Dangerzone error that manifested in recent Debian-based environments that included both PySide6 and PySide2 libraries (#1218)
  • Issue templates have been updated to work on Windows (#1237)
  • Question dialogs now show a question mark instead of an alert (#1198)

Changed¶

  • Update our container image from Debian Bookworm to Debian Trixie (#1243)
  • Upgrade the bundled LibreOffice version from 7.x to 25.x, as a result of our Debian Trixie switch (#1165)

Platform changes¶

  • Add support for Ubuntu 25.10 (Questing Quokka) (#1264)
  • Add support for Fedora 43 (#1263)
  • Add support for the new Debian Testing (Forky) (#1265)
  • Drop support for Ubuntu Oracular (24.10) since it is end of life (#1246)
  • Add a deprecation warning for Debian bullseye (#1214)

Development changes¶

  • Use the archived backports for Debian bullseye (#1213)
  • Install numpy 2.0.0 in Python 3.9 envs, and use more recent numpy in Python environments >= 3.10, to avoid some compatibility issues with Python 3.13 (#1206)
  • Improve our release instructions by splitting the large RELEASE.md file into distinct docs, whose instructions can be executed sequentially (#1212)
  • Run our full CI test suite on Windows and macOS GitHub runners (#1009)
  • Add end to end functional tests for independent container updates (#1157)
  • Add developer instructions for releasing container images independently (#1162)
  • Do not check the Git commit/branch when attesting provenance info (#1270)

0.8.0 - 2024-11-06¶

Added¶

  • Point to the installation instructions that the Tails team maintains for Dangerzone (announcement)
  • Installation and execution errors are now caught and displayed in the interface (#193)
  • Prevent users from using illegal characters in output filename (#362). Thanks @bnewc for the contribution!
  • Add support for Fedora 41 (#947)
  • Add support for Ubuntu Oracular (24.10) (#954)

Fixed¶

  • Update our macOS entitlements, removing now unneeded privileges (#638)
  • Make Dangerzone work on Linux systems with SELinux in enforcing mode (#880)
  • Process documents with embedded multimedia files without crashing (#877)
  • Search for applications that can read PDF files in a more reliable way on Linux (#899)
  • Handle and report some stray conversion errors (#776). Thanks @amnak613 for the contribution!
  • Replace occurrences of the word "Docker" in Podman-related error messages in Linux (#212)

Changed¶

  • The second phase of the conversion (pixels to PDF) now happens on the host. Instead of first grabbing all of the pixel data from the first container, storing them on disk, and then reconstructing the PDF on a second container, Dangerzone now immediately reconstructs the PDF on the host, while the doc to pixels conversion is still running on the first container. The sanitation is no less safe, since the boundaries between the sandbox and the host are still respected (#625)
  • PyMuPDF is now vendorized for Debian packages. This is done because the PyMuPDF package from the Debian repos lacks OCR support (#940)
  • Always use our own seccomp policy as a default (#908)
  • Debian packages are now amd64 only, which removes some warnings in Linux distros with 32-bit repos enabled (#394)
  • Allow choosing installation directory on Windows platforms (#148). Thanks @jkarasti for the contribution!
  • Bumped H2ORestart LibreOffice extension to version 0.6.6 (#943)
  • Platform support: Ubuntu Focal (20.04) is now deprecated, and support will be dropped with the next release (#965)

Removed¶

  • Platform support: Drop Ubuntu Mantic (23.10), since it's end-of-life (#977)

Development changes¶

  • Build Debian packages with pybuild (#773)
  • Test Dangerzone on Intel macOS machines as well (#932)
  • Switch from CircleCI runners to Github actions (#674)
  • Sign Windows executables and installer with SHA256 rather than SHA1 (#931). Thanks @jkarasti for the contribution!

0.6.0 - 2024-02-26¶

Added¶

  • Platform support: Fedora 39 (issue #606)
  • Add new file formats: epub svg and several image formats (BMP, PNM, BPM, PPM) (issue #697)

Fixed¶

  • Fix mismatched between between original document and converted one (issue #626). This does not affect the quality of the final document.
  • Capitalize "dangerzone" on the application as well as on the Linux desktop shortcut, thanks to @sudwhiwdh #676
  • Fedora (Linux): Add missing Dangerzone logo on application launcher (issue #645)
  • Prevent document conversion from failing due to lack of space in the converter. This affected mainly systems with low computing resources such as Qubes OS (issue #574)
  • Add a missing dependency to our Apple Silicon container image, which affected dev environments only, thanks to @prateekj117 (#671)
  • Development: Add missing check when building container image, thanks to @EtiennePerot (#721)

Changed¶

  • Feature: Add support for HWP/HWPX files (Hancom Office) for macOS Apple Silicon devices (issue #498, thanks to @OctopusET)
  • Replace Dangerzone document rendering engine from pdftoppm PyMuPDF, essentially replacing a variety of tools (gm / tesseract / pdfunite / ps2pdf) (issue #658)
  • Changed project license from MIT to AGPLv3 (related to issue #658)
  • Containers: stream pages instead of mounting directories. For users in practice this doesn't change much, but it opens up technical possibilities that go from security to usability. (issue #443)
  • Ubuntu Jammy (Linux): add external depedency (provided by the Dangerzone repository) which fixes podman crashing during standar stream I/O (issue #685)

Removed¶

  • Removed timeouts (issue #687)
  • Platform support: Drop Ubuntu 23.04 (Lunar Lobster), since it's end-of-life (issue #705)
